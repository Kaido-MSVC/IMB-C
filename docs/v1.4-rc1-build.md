# IMB-C 1.4.0-rc.1 來源重建說明

來源包的 source 目錄含本候選實際建置的 Rust／Slint 程式、Windows 資源、Cargo.lock、測試與公開建置腳本；native-materials/licenses 含第三方條文、署名、原生對應來源及建置材料。沒有私人 iat、私人圖片、PDB 或本機帳本。

## 應用程式

請在新解壓的 source 目錄建置，保留既有正式版、工作目錄與封包。

需要 Windows x64、Rust 1.100.0 MSVC toolchain、MSVC C++ build tools 與 Windows SDK resource compiler。進入 source 目錄執行：

```powershell
cargo build --locked --release --bin imb-c --bin imb-c-cli
```

相依版本由 Cargo.lock 固定。第一次建置需要已有相依快取或可存取 crates.io；本來源包沒有宣稱包含全部 Rust 套件原始碼或能在空快取離線建置。build.rs 會以 SDK rc.exe 分別建立兩個執行檔的圖示及版本資源。

## 執行期

Rust EXE 之外仍需要同版 Portable 內的 ImageMagick、JXL 與執行期 DLL。只使用本 RC1 Portable 或已符合 RUNTIME-MANIFEST-v1.4.json 的輸入，將這 59 個項目依清單複製到 target/release，並在複製前後以 SHA-256 核對；不要複製 Portable 內的舊 EXE 覆蓋新建置的 EXE。清單沒有列入的執行檔或外部工具不得自動帶入。

也可以在新的目錄使用 scripts/build-v14.ps1，提供符合 RUNTIME-MANIFEST-v1.3.json 的既有基線；腳本會驗證完整輸入、複製固定 runtime、套用 v1.4 policy，並重新建置 GUI／CLI。這個入口不接受已經套用 v1.4 policy 的基線。原生 runtime 本輪沒有重建，其對應來源與歷史建置說明位於 native-materials/licenses；重新建置原生相依需要相應工具鏈與來源材料，不能只靠 Rust Cargo 完成。

RC1 執行檔使用 --remap-path-prefix 移除工作站路徑；重建者可自行設定其來源及使用者目錄對應。這不構成逐位元組可重現建置保證。封裝驗證記錄提供實際交付雜湊。

## 驗證

一般檢查使用 cargo fmt --check、cargo check --locked、cargo test --locked、cargo clippy --locked --all-targets -- -D warnings 與 cargo audit。runtime、SMB、私人素材及 iat 入口需要另外提供環境；條件不足時不得把 ignored 或內部略過算成已通過。RC1 的實際分類與結果見隨附審查及驗收報告。
