# RC2 JPEG XL 來源與重建

RC2 有兩組 JPEG XL 二進位。ImageMagick 的 `CORE_RL_jpeg-xl_.dll` 與 `CORE_RL_brotli_.dll` 由 IMB-C 建置。Portable 的 `JXL/cjxl.exe` 與 `JXL/djxl.exe` 來自 libjxl 的 Windows x64 靜態發行附件。兩組交付的雜湊及來源見來源包的 `native-materials/jxl-rc2/RC2-SOURCES.json`。

## 固定來源與修改

| 元件 | 版本與 commit | 條文 |
| --- | --- | --- |
| libjxl | v0.13.0，`5a7da83447212fe4900fc29ce97430b881caa67e` | BSD-3-Clause、PATENTS |
| Brotli | v1.2.1，`db24a98aed38a16de78cc05ca15cdd8dc2a0d92d` | MIT |
| Highway | `457c891775a7397bdb0376bb1031e6e027af1c48` | Apache-2.0 |

三者完整快照位於 `native-materials/jxl-rc2/libjxl-0.13.0-brotli-highway-source.zip`。IMB-C 沿用未修改的上游來源，另以匯出定義、Windows 版本資源及 MSVC 選項產生與 ImageMagick 相容的 DLL。Highway 靜態連入 JPEG XL DLL。Brotli 與 Little CMS 2.19.1 由該 DLL 動態連結。ImageMagick 本身的組態隔離、AVIF、PSD 補丁及組態來源位於 `native-materials/licenses/security-20261112/` 和 `security-20261113/`。

`native-materials/licenses/jxl-tools/` 保留條文、授權告知、AUTHORS 與 PATENTS。原 RC2 內嵌清單固定了該目錄的部分歷史檔案摘要，所以核對此版工具來源時請以 `RC2-SOURCES.json` 的 v0.13.0 附件索引為準。

## 重建 ImageMagick 的兩份委派 DLL

在 Windows x64 使用 Python 3.14、CMake 4.5、Ninja 1.13、Visual Studio 2026 MSVC 14.52.37025 與 Windows SDK 10.0.28000.0。解壓 RC2 Portable 作為 ABI 及 Little CMS 參照。來源包根目錄下可執行：

```powershell
python -X utf8 source/scripts/rebuild-rc2-jxl-delegates.py `
  --snapshot native-materials/jxl-rc2/libjxl-0.13.0-brotli-highway-source.zip `
  --imagemagick-source native-materials/licenses/ImageMagick-7.1.2-34-selected-corresponding-source.zip `
  --portable C:/rc2/portable --work C:/rc2/jxl-delegates `
  --vs 'C:/Program Files/Microsoft Visual Studio/18/Community'
```

腳本核對來源和三個 ABI 參照的 SHA-256，再於新的建置目錄輸出 DLL。首次替換請在另一份測試副本使用。以 ImageMagick 檢查小圖無損往返，再依 [LGPL 與內嵌清單說明](../LGPL-REPLACEMENT.md) 的相同清單流程，在自己的 GUI／CLI 建置中採用新檔。

## 上游 cjxl／djxl 靜態工具

上游 `jxl-x64-windows-static.zip` 的 SHA-256 為 `e394519c05ea9e5b83947f89b40afbf1ea7c631a608406c5de945a4c5bdcdcb7`。要取得 RC2 原始位元組，請核對該附件及 ZIP 內的 `x64-windows-static/bin/cjxl.exe`、`djxl.exe`。

原建置使用 `release.yaml` 的 `windows_build`、`x64-windows-static` Release 工作，交付 EXE 回報 Clang 22.1.3。來源包附 SJPEG、skcms、Little CMS 的上游 gitlink 快照及 vcpkg 2025.10.17 配方。上游預設啟用 skcms，且該工作關閉 viewer 與外掛。Little CMS gitlink 供其他組態重建參考。來源包的 `native-materials/jxl-rc2/vcpkg-source-cache/` 附五個原生函式庫的上游來源檔。把它們複製到新的下載目錄，並將 `VCPKG_DOWNLOADS` 設為該目錄，即可由 vcpkg 依配方核對並使用。其餘建置工具由 vcpkg 依配方取得。

```powershell
python -X utf8 source/scripts/prepare-rc2-jxl-tools.py `
  --archives native-materials/jxl-rc2 --work C:/rc2/jxl-tools
```

在剛建立的 `C:/rc2/jxl-tools` 下，使用 `vcpkg/bootstrap-vcpkg.bat -disableMetrics` 準備該版本的工具，再依上游工作安裝 `giflib libjpeg-turbo libpng libwebp pkgconf`。下列是本機實測的 Ninja 路徑。請在 Visual Studio 2026 的 x64 開發環境中執行，並依安裝位置設定 `$clang`：

```powershell
./vcpkg/vcpkg.exe install --triplet x64-windows-static giflib libjpeg-turbo libpng libwebp pkgconf
$toolchain = (Resolve-Path ./vcpkg/scripts/buildsystems/vcpkg.cmake).Path
$clang = 'C:/Program Files/Microsoft Visual Studio/18/Community/VC/Tools/Llvm/x64/bin/clang-cl.exe'
$pkgconf = (Resolve-Path ./vcpkg/installed/x64-windows-static/tools/pkgconf/pkgconf.exe).Path
$env:PKG_CONFIG_PATH = (Resolve-Path ./vcpkg/installed/x64-windows-static/lib/pkgconfig).Path
cmake -G Ninja -S libjxl-0.13.0 -B build `
  -DCMAKE_BUILD_TYPE=Release -DCMAKE_TRY_COMPILE_CONFIGURATION=Release `
  -DCMAKE_C_COMPILER="$clang" -DCMAKE_CXX_COMPILER="$clang" -DPKG_CONFIG_EXECUTABLE="$pkgconf" `
  -DCMAKE_TOOLCHAIN_FILE="$toolchain" -DVCPKG_TARGET_TRIPLET=x64-windows-static `
  -DX_VCPKG_APPLOCAL_DEPS_INSTALL=OFF -DJPEGXL_VERSION=5a7da83 `
  -DJPEGXL_STATIC=ON -DJPEGXL_ENABLE_TOOLS=ON `
  -DBUILD_TESTING=OFF -DJPEGXL_ENABLE_OPENEXR=OFF -DJPEGXL_ENABLE_PLUGINS=OFF `
  -DJPEGXL_ENABLE_TCMALLOC=OFF -DJPEGXL_ENABLE_VIEWERS=OFF -DJPEGXL_ENABLE_DEVTOOLS=ON
cmake --build build --target cjxl djxl
```
