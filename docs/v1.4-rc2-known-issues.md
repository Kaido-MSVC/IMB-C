# IMB-C 1.4.0-rc.2 已知問題與殘餘風險

本候選僅供個人使用或少量分享，且只處理受信任圖片。原生引擎在各工作獨立的 AppContainer 內執行，可限制引擎對檔案及網路的存取。任意惡意圖片仍超出本候選的使用範圍。

## P1 狀態

- **磁碟硬配額（部分修正，仍保留 P1）**：第二輪起，來源複製與 identify 之前就跨執行個體預留本機暫存，JPEG ↔ JXL 也有預留，本機暫存與輸出磁碟分開計算並在寫入輸出前以目錄控制代碼檢查剩餘空間。引擎可寫位置已由 AppContainer 限定為本次暫存樹（OS 強制）；整棵暫存樹以即時大小每約 40 ms 輪詢（修正舊做法對仍開啟檔案的大小落後）。IMB-C 寫入的累計上限仍是固定 32 GiB，與預留量不相等（對齊嘗試使合法 100 MP AVIF 失敗而撤回）。暫存樹大小與剩餘空間仍是輪詢後終止，不是檔案系統硬配額：遭利用的引擎可在一次輪詢間隔內短暫佔用剩餘空間，隨後被終止並清理。Windows 的 NTFS 配額或固定大小 VHDX 需要系統管理員權限，本輪未採用。沒有在真實磁碟上做寫滿測試。
- **工作隔離（已修正，實測）**：不同工作使用不同 AppContainer SID，彼此的暫存不可讀寫，程序也無法以修改權限開啟。未授權的使用者檔案連讀取都被拒絕；沒有網路 capability。仍可讀取系統位置（System32、Program Files）。核心漏洞逃逸不在範圍內；同使用者的非 AppContainer Low IL 程序仍可寫入 IMB-C 的 Low 標籤暫存（與舊版相同）。

## runtime 快取（第二輪 H2）

IMB-C 不再修改 Portable 資料夾的 ACL；唯讀解壓目錄也可使用。第一次轉檔時，清單內的 ImageMagick／JXL 檔案經 SHA-256 核對後複製到 `%LOCALAPPDATA%\IMB-C\engine-runtime\<版本>-<清單雜湊>`，每個檔案與目錄設定不繼承的唯讀 DACL，使用期間以控制代碼鎖定。快取位置必須是本機 NTFS，否則拒絕轉檔。第三輪起回收採預設拒絕：只回收所有權登錄中、File ID 相符且沒有其他程序使用的舊版快取，未知目錄與清單外內容一律保留（第二輪建立、沒有登錄的舊快取不會自動刪除）；移除 IMB-C 後可手動刪除該資料夾。同使用者的一般權限程式仍可改寫自己擁有檔案的 DACL，這類竄改會在下次啟動驗證時被丟棄重建，但程序執行期間不會即時偵測（與替換 imb-c.exe 屬同一信任層級）。

快取回收同時比對版本目錄及各子項的 File ID。只帶有舊版名稱紀錄的子項會保留。隔離的 `quarantine-*` 目錄可能含有其他內容，程式會保留供使用者確認，長期累積可能占用磁碟。

## 檔案系統邊界

RC2 先前直接拒絕 FAT／exFAT 來源與輸出，但這只約束當次路徑。現在 AppContainer 無法以路徑開啟無 ACL 卸除式 exFAT 磁碟區或 SMB 共用上的檔案（以卸除式 exFAT 裝置及本機 SMB 迴路唯讀實測）。遠端與檔案系統能力都由同一個已開啟的控制代碼判定（第二輪 H3）。來源不在本機 NTFS 時，IMB-C 從已開啟的控制代碼複製到受控暫存，引擎只拿副本。輸出先在本機受控暫存完成全部驗證（含 JPEG ↔ JXL 往返），再由 IMB-C 以固定的目的目錄控制代碼建立、讀回比對並不覆寫發布；引擎從不取得目的端控制代碼，因此 FAT／exFAT／SMB 輸出目錄可以使用。磁碟區能力無法由控制代碼判定時拒絕。轉檔期間來源以只共享讀取開啟，正被其他程式寫入的來源會被拒絕。

第二輪在實體卸除式 exFAT 與本機 SMB 迴路實測：來源與輸出都在該媒體上轉檔成功，引擎只取得本機受控暫存的控制代碼，同名不覆寫、目的目錄固定期間不可改名、來源 SHA-256 不變（只建立並刪除測試自己的資料夾）。未實機驗證：FAT32、固定磁碟上的 FAT／exFAT、其他卸除式裝置、實體 ReFS、非本機 SMB／NAS；不支援以目錄控制代碼相對建立或改名的檔案系統會在交付時失敗並刪除暫存，不會退回以路徑發布。

輸出暫存若無法刪除（例如 SMB 中斷），錯誤會列出暫存位置且不發布；下次啟動時依擁有權紀錄核對 File ID 後回收，檔案系統沒有可靠 File ID 時需手動刪除。實際斷網情境未實測（以注入失敗模擬）。

## GUI 關閉

關閉主視窗會要求取消，背景工作完成程序與暫存清理後才退出。若外部工具同時關閉 winit 內部的事件視窗，事件迴圈可能收不到結束訊息。此時看門狗在約 5 秒後接手，等背景工作全部完成才結束程序。遠端同步 I/O 若長時間未返回，主視窗隱藏後程序可能仍在等待。

## iat、佇列與驗證

iat 預設停用；使用者明確啟用後，外部 iat 以 Medium IL 再解析圖片，不受 ImageMagick 引擎的 AppContainer 與 policy 保護。不隨附私人 iat、原始碼、PDB 或測試素材。工具缺少、版本不合或執行失敗不刪除已完成輸出，也不跳過既有核心驗證。

外部 Job 原子納管、KILL_ON_JOB_CLOSE、明確初始 commit／buffer 參數、受驗證的單次重試上限與外層 Job 記憶體上限共同限制執行。跨執行個體預留涵蓋本次上限及額外開銷，確認工作樹退出才釋放；無法證明停止時保留預留及暫存。

驗證仍是單一消費者、有界佇列 8；最多兩項轉檔不等待 iat 排空。大批次滿載時可能有未檢查項目，逐檔警告會明示佇列滿載，不等於使用者取消、驗證失敗或圖片損壞。介面另顯示已完成／已排入驗證數量，批次等待已接受項目處理完成。沒有自動補排保證。保留這項限制，避免改成無界佇列或讓轉檔工作長時間阻塞。

iat 以當時路徑內容比對，沒有把發布時的 File ID／SHA-256 或 iat 二進位身分鎖定到結果。同一使用者替換路徑的 TOCTOU 仍存在；結果不構成最初發布內容的密碼學證明。勿在比對期間替換來源、輸出或外部工具。

## 載入、格式及發布限制

（Runtime 更新後）GUI／CLI 改用靜態 CRT，不再匯入 VCRUNTIME140，程式根目錄也不再隨附任何 DLL。啟動相依 DLL 與 SetDefaultDllDirectories 都改為只允許 SYSTEM32（0x800），應用程式目錄、目前目錄與 PATH 都不在搜尋範圍內，因此在應用程式目錄放入同名 DLL 不會被 GUI／CLI 載入。原生引擎是另一個程序，從經 SHA-256 驗證並鎖定的 runtime 快取啟動。這仍不是簽章驗證或 Windows 系統 DLL 身分鎖定；請解壓至信任的目錄。（更新前為 APP_DIR | SYSTEM32 (0xA00)。）

輸出先在本機受控暫存驗證，再寫入目的端並讀回比對。第三輪獨立驗收的 Release 以同一張 100 MP 來源測得 AVIF 有損約 439 秒、WebP 無損約 183 秒，兩者皆完成。JXL 無損在編碼前因系統可用 committed memory 不足而拒絕，沒有發布新檔。單檔總期限維持 600 秒，較慢的主機仍可能逾時。

AVIF 真無損限既有支援的 8-bit RGB／RGBA；CMYK、HDR 及不支援的精度會安全拒絕或依既有契約處理。JXL ICC 不可安全保留時拒絕；PSD／PSB 是 composite，並不重建圖層。iat 無法判定不表示圖片已損壞，也不能宣稱已驗證無損。詳見 CLI JSON 契約。

RC2 MSI 已通過 ICE、管理解包及解包後煙霧測試。**乾淨 Windows 的 MSI 安裝生命週期為 SKIP**，包含完整安裝、修復、解除安裝及升級。執行檔與 MSI 均未簽章。SmartScreen 及實體 ReFS 也未驗證。第三輪的 RustSec 檢查涵蓋 Rust 套件，當時有 7 項停止維護的依賴。
