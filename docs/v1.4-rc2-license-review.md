### 1.2 是否必須在 GitHub 下載前逐人取得明確同意

**答：Microsoft 條文沒有這項要求。**

- Community §5(c)(ii) 只要求「require … to agree to terms」，沒有寫「下載前」「逐人」「保存同意紀錄」或「點選同意」。
- Runtime 條款本身以「使用即接受」的方式成立（BY USING THE SOFTWARE, YOU ACCEPT THESE TERMS）。
- 前一輪文件裡的「先提供全文 → 收到明確回覆 → 才交付」「受控入口、短效連結、匿名使用者不得取得」都是**專案自行採取的保守政策**，不是 Microsoft 的強制要求。這些做法來自 v1.1.1 到 v1.3.x 的好友交付流程（`RUNTIME-HANDOFF.md`）。

### 1.3 仍需判斷的部分（NEEDS REVIEW）

1. **Portable 的同意機制。** 條文沒有規定形式，但「只隨包附上條款」或「在發行頁寫明使用即同意」是否足以構成「require … to agree」，屬於契約成立方式的法律判斷，本輪無法確認。可降低風險的做法，依保守程度排列：(a) GitHub 發行頁與下載說明明確告知「下載或使用即表示同意隨附的 Microsoft Runtime 條款」，並附上連結；(b) 只公開 MSI，因為 MSI 已有安裝時的明示同意；(c) 下一版在 Portable 首次啟動時要求接受條款；(d) 維持原本的保守政策，也就是逐人或受控入口。
2. **隨包的接收文件已過時。** RC2 內的 `RUNTIME-RECIPIENT-TERMS.md` 仍是 `IMBC-RUNTIME-2026-10-27-v1.1.1-r1`，第 2、3 點以「好友交付」為前提。`RUNTIME-HANDOFF.md` 仍是 v1.3.0 流程，回覆範本也寫著「請提供 IMB-C v1.3.0」。內含的 Microsoft 官方條款全文正確，保護程度不低於原條款，但文件描述的交付情境與公開下載不符。修改這兩份文件需要重新封裝，超出本輪範圍。若沿用原封包，應在發行頁說明這兩份文件的適用方式。

### 1.5 技術落差（非授權問題，但與 Microsoft 部署要求相關）

Microsoft 部署說明：「The version of the Redistributable installed on the machine must be the same or later than the version of the MSVC Build Tools used to create your application.」

RC2 共有 18 個動態 CRT 二進位以 **MSVC 14.52** 連結（PE linker 版本），包括 `imb-c.exe`、`imb-c-cli.exe`、`CORE_RL_MagickCore_.dll`、`CORE_RL_MagickWand_.dll`、`magick.exe`、`heif.dll`、`CORE_RL_jpeg-xl_.dll`、`CORE_RL_brotli_.dll` 及 10 個 coder。隨包並優先於 app-local 載入的 Runtime 卻是 **14.51.36247**。既有煙霧測試與回歸都通過，但這不符合 Microsoft 公開的版本相容要求，可能在特定 API 路徑發生未定義行為：**NEEDS REVIEW**。修正方式是在下一個候選版改用 ≥ 14.52 的 Runtime（本機 default 為 14.52.37025，DLL 版本 14.52.37029），但這會改變 Runtime 清單、內嵌雜湊與封包，本輪依限制不做。

**現有 RC2 封包能否直接公開發布：維持 BLOCKED。** 原因已經不是「Microsoft 要求下載前逐人同意」，這個前提不成立。仍然 BLOCKED 是因為還有三項事情要由發行者決定：

1. 選擇 Portable 的同意實現方式（1.3 的 a 到 d）。若選 (a)，要接受「隨包附條款＋發行頁告知」是否足夠的法律不確定性。
2. 接受隨包接收文件與公開下載情境不符，並在發行頁補充說明；或者改為重新封裝。
3. 接受 Runtime 14.51 舊於 14.52 建置工具的技術風險，作為 Pre-release；或者下一個候選版改用 ≥ 14.52 的 Runtime 並重新驗收。

發行者對三項都做出明確決定後，授權面沒有發現 Microsoft 條文禁止以 GitHub Pre-release 公開提供含 app-local Runtime 的封包。本輪沒有發布任何檔案。

## 6. 簡化 Runtime 條款流程（2026-11-19）

第 5 節的程式內同意流程（GUI 首次啟動條款視窗、CLI `runtime-terms` 指令與單次接受參數、同意紀錄與條款雜湊驗證、runtime 閘門）超出 Microsoft 條文的要求，影響正常啟動與轉檔，已移除。§5(c)(ii) 只要求散布者「要求」終端使用者同意保護程度不低於原條款的條款，沒有規定形式；現行做法：

| 交付方式 | 做法 |
| --- | --- |
| MSI | 標準授權對話方塊顯示 `RUNTIME-RECIPIENT-TERMS.md`（含官方全文），須勾選同意；靜默安裝須 `ACCEPTTERMS=1` |
| Portable ZIP | 根目錄隨附條款全文與官方 DOCX；條款載明使用即表示同意，與 Microsoft Runtime 條款本身「BY USING THE SOFTWARE, YOU ACCEPT THESE TERMS」的成立方式相同 |
| 發行頁 | 依 1.3 的 (a)，寫明封包含 Microsoft Runtime、下載或使用即表示同意，並附條款連結（建議文字見 `RUNTIME-HANDOFF.md`） |

其餘結論不變：DLL 未修改、14.52.37029.0 正式版、來源與簽章證據、58 項 manifest、只交付完整封包、LGPL 權利保留。使用者既有的 `runtime-terms-acceptance.json` 不再讀取，也不刪除。本節不是法律意見。
