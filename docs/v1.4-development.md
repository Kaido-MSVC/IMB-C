# v1.4 開發候選

這是本機開發候選，不是正式 1.4.0 發布。穩定版文件與 1.3.3 封包保留。

## 使用

GUI 與 `imb-c-cli.exe` 共用引擎；CLI 不初始化 GUI。例：

```powershell
.\imb-c-cli.exe convert .\input.png --output-dir .\output --format avif --mode lossless
.\imb-c-cli.exe convert --input-dir .\images --recursive --output-dir .\output --format jxl --mode lossy --quality 75 --report-json .\new-summary.json
```

輸出資料夾必須存在。來源唯讀，同名輸出自動編號；報告必須是新檔。CLI stdout 每檔一行 JSON，stderr 為診斷；退出碼 0 代表轉檔完成、1 為部分轉檔失敗、2 為參數／環境／報告錯誤、130 為取消。外部驗證結果不改寫轉檔成功狀態。

## 格式與限制

- AVIF 真無損是明確選項：quality 100、speed 6、identity matrix、full range、4:4:4，且必須通過既有逐樣本驗證。只開放未套用 ICC 轉換的 8-bit RGB／RGBA 來源；16-bit 來源仍拒絕，不以 12-bit 編碼冒稱無損。ICC 有明確 CICP 標籤時沿用 primaries／transfer；無法從任意 ICC 推導時保持 unspecified，ICC 原文仍須完全相同。只有外部 iat 的 `output.avif.pixel_verified=true` 才標示其 AVIF 像素實證。
  無色彩標記的來源不猜成 sRGB，保留 unspecified 並警告；只有 cHRM／gAMA、沒有可確認 sRGB 或 ICC 的 PNG 會拒絕此模式。相容讀回本版明確未指定色彩的 identity AVIF，仍附加色彩未確認警告。
- JXL 預設無損；有損品質 1–99。一般像素編碼與 JPEG 原始位元組封裝是獨立流程。兩者都保留原有驗證。有損輸出的 Alpha 必須逐值相同，位深與 ICC 仍檢查；部分 ICC 會被隨附編碼器改寫，此時安全拒絕並提示改用無損，不能以「色彩看起來相同」略過雜湊比對。
- PSD v1／PSB v2 讀取儲存的合成影像，副檔名不決定 Photoshop 版本。保留空名稱資源正規化，避免其後 ICC 遺失。不帶 Alpha 的 8-bit PSD 不再一律升為 16-bit；ICC 轉換等會增加精度的操作另行回報。
- PSD／PSB 寫出一個圖層及合成影像，使用 RLE；不保留原圖層。帶 Alpha 的來源安全拒絕輸出 PSD／PSB，避免白色混合造成樣本改變。PSD／PSB 帶 Alpha 的輸入仍由既有解碼器反混合，會附加語意警告，不能宣稱原始合成樣本無損。
- PSD 每邊 30000 上限保留；較大尺寸須明確選 PSB，但仍受 32768、400 MP、記憶體、暫存與期限限制。本版沒有放寬到 PSB 格式理論上限。

## 選用外部驗證

iat 是選用的外部驗證工具，不隨 IMB-C 發布。預設停用；保留偏好設定內明確儲存的選擇。GUI 須勾選啟用，CLI 須使用 `--iat <絕對路徑>` 或 `--no-iat`。設定非空時只使用指定的絕對路徑，錯誤會回報且不回退；設定空白才使用應用程式旁的 `iat.exe`；不搜尋 PATH 或目前工作目錄。需要同目錄的 worker、iat ≥0.5.1、Schema ≥1.1 且主版本為 1。

輸出完成並關閉後，才在背景啟動 Medium IL 的 iat，不放進引擎 Low IL Job。版本探測 10 秒，外部驗證每次 720 秒；獨立外層 Job 在建立主程序時以 JOB_LIST 原子納管，不設 UI／breakaway 限制；iat 自身的 worker Job 形成巢狀關係。正常完成、取消及逾時均停止並確認整棵程序樹 active=0；未確認停止時保留資源預留與暫存。每程序最多一個外部驗證，記憶體參與跨執行個體預留。退出碼 0–5、無報告、壞報告、Schema 不相容、逾時與取消分開回報。退出碼 4 只有合法且受上限約束的 `resource_need` 才重試一次，使用新報告；不執行報告內的任意命令文字。

iat 缺少或失敗時，原有轉檔繼續。外部結果不能刪除或覆寫來源及已完成輸出。GUI 清除資料夾設定只重設選取／記憶路徑，不刪除磁碟內容。

## 建置與驗證

使用 `scripts/build-v14.ps1`，以既有 1.3.3 runtime 為唯讀基線，指定新的候選目錄；不對穩定版目錄建置。`prepare-v14-runtime.py` 先完整驗證基線，再複製並只替換候選 policy，最後驗證候選與基線。

外部工具測試透過 `IMBC_TEST_IAT` 指定，未設定則略過；CLI 整合測試透過 `IMBC_TEST_CLI` 指定。核心格式測試透過 `IMBC_TEST_ENGINE` 指定候選 runtime。既有 acceptance／verify 支援 `IMBC_TEST_ENGINE` 與 `IMBC_TEST_OUTPUT`，可避免測到穩定版 runtime 或寫入歷史測試輸出。

仍有原生暫存無硬配額、不同 Low IL 工作未完全隔離兩項已知風險；本版沒有取消任何原有安全限制。DNG 評估見 [候選評估](v1.4-dng-evaluation.md)，尚不啟用。


## 獨立驗證佇列與安全界線

GUI 轉檔池仍最多兩項並行。轉檔完成後以非阻塞提交交給單一 iat 消費者；最多 8 項等待，滿載或消費者關閉會在該檔與警告報告記錄「iat 未檢查」，不刪除輸出。完成張數代表轉檔完成；iat 完成數另外顯示。批次仍為忙碌狀態，直到已接收的驗證結束並結算警告統計。取消會讓執行中驗證停止，佇列內項目回報取消而不再啟動工具。

iat 以 Medium IL 解析來源，並非 Low IL 沙箱；外層 Job 只管理生命週期，不能防止解碼器利用一般使用者權限。啟用前應信任圖片與工具。iat 不相容、缺少或失敗時，原引擎流程繼續，外部驗證不決定刪檔或輸出發布。

iat 暫存沿用本機 NTFS 根目錄、擁有權日誌與 File ID 核對。只有外部報告目錄允許 WRITE sharing 以支援工具的原子重新命名，仍不允許 DELETE sharing；沒有放寬 Low IL 引擎目錄。下次啟動只回收已死亡執行個體日誌所記錄、原始 File ID 相符、非重新解析點且未使用中的項目，不依名稱或年齡掃除 `imb-c-iat-*`。仍存活的 IMB-C 日誌由存活鎖保護。

CLI 只在 `convert`、`--help`、`--version` 等明確入口啟動；檔案或未知啟動參數會開 GUI，本輪沒有實作拖入自動加入清單。Windows subsystem 沒有輸出串流時用訊息視窗回報 CLI 結果，完整 JSON 與診斷建議使用 `imb-c-cli.exe`。`convert --help` 支援說明；無損模式禁止 `--quality`，`--iat` 與 `--no-iat` 不可同時使用。JSON 路徑只轉換顯示文字，實際存取仍使用原始 `PathBuf`。

Ctrl+C／Ctrl+Break 使用原子取消旗標。Close／Logoff／Shutdown 僅設定旗標後允許 Windows 結束程序，不保證 Rust 解構器可執行；互動程序也不保證收到登出／關機通知。子程序依 Job 最後控制代碼關閉而退出，具名殘留依下次啟動的擁有權日誌回收。沒有以實際登出或關機中斷使用者的桌面來驗收。

Win32 依據：[巢狀 Job](https://learn.microsoft.com/en-us/windows/win32/procthread/nested-jobs)、[啟動屬性與 JOB_LIST](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute)、[主控台通知限制](https://learn.microsoft.com/en-us/windows/console/handlerroutine)。Context7 沒有適用的原生 Win32 文件，因此查閱 Microsoft 官方文件。
